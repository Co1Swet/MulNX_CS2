# 停止游戏内 MulNX

向游戏内 WebSocket 网关发送：

```json
{"type":"System/Stop","payload":""}
```

请求通过既有消息总线通知原启动线程，复用正常清理流程停止模块、汇合工作线程并卸载游戏内 DLL。不弹确认窗口，不退出 CS2，也不删除软件文件；普通启动、`auto.yaml` 和原有手动退出行为保持不变。重复请求只通知一次。

网关回执仍只表示已入队，不表示已经停止；清理时连接会断开，断开本身也不能证明 DLL 已卸载。

需要确认完成的调用方可以在发送停止请求前，以 `SYNCHRONIZE` 权限打开并持有同一 Windows 会话中的手动重置事件 `Local\MulNX_CS2_UnloadReady_<游戏进程PID>`。事件不存在或打开失败时，不能确认清理完成。停止后等待该事件：它只在模块清理、任务线程汇合和核心对象销毁后发出，表示即将调用 `FreeLibraryAndExitThread`，并不表示 DLL 已卸载。随后检查同一游戏进程中的 `CS2OBTool.dll` 模块，确认其已不存在，才可认定卸载完成；检查失败或超时应视为状态未知。进程退出也应单独处理。完成后关闭事件句柄；每次重新注入时重新打开，避免复用旧周期的句柄。
